# 폰켓몬 (프로그래머스 Lv1, 해시)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/1845

## 문제

N마리의 포켓몬 중 최대 N/2마리를 가져갈 수 있을 때, 서로 다른 포켓몬의 종류를 최대로 하려면 몇 종류를 가져갈 수 있는지 구하기.

## 접근

- 가져갈 수 있는 최대 수량(`maxValue = nums.length / 2`)과 실제 존재하는 포켓몬 종류 수(`중복 제거한 개수`)를 비교
- 종류 수가 `maxValue`보다 많으면 `maxValue`만큼만 가져갈 수 있고, 적으면 있는 종류를 다 가져가면 됨 → 둘 중 작은 값이 정답
- 처음엔 `HashMap<Integer, Integer>`로 각 포켓몬 번호별 등장 횟수까지 저장했는데, 문제 풀이에는 등장 횟수(value)는 전혀 쓰이지 않고 **종류 수(size)만 필요**했음 → `HashSet<Integer>`로 바꾸면 목적에 더 맞고 코드도 간결해짐

## 헷갈렸던 지점

- 필요한 게 "카운팅"이 아니라 "중복 제거"라는 걸 바로 못 알아채고 Map부터 꺼내 썼음. 자료구조 선택 전에 "이 값으로 뭘 할 건지"부터 따져봤어야 함

## 실수

1. `pokemons.getOrDefault(nums, 0)` — 키로 `num`(현재 원소) 대신 `nums`(배열 자체)를 넣는 오타. `getOrDefault`의 파라미터 타입이 `Object`라 컴파일 에러 없이 통과됨
    - 결과적으로 항상 0을 반환해 모든 값이 1로 덮어써졌지만, 최종적으로 필요한 건 `size()`(키의 개수)뿐이라 답에는 영향이 없었음 → 로직이 망가졌는데도 테스트를 통과한 케이스. 요구사항이 우연히 버그를 가려준 것뿐, 다른 조건이 추가됐다면 바로 드러났을 문제
2. 사용하지 않는 `count` 변수 선언 — 죽은 코드
3. 맵 변수명을 `ponkemons`로 선언해놓고 마지막 줄에서 `pokemons`로 참조 — 컴파일 에러

## 회고

- "통과했다 = 로직이 맞다"가 아니라는 걸 직접 겪은 문제. `getOrDefault(nums, ...)` 버그는 테스트 케이스로는 못 잡히는, 요구사항 특성 덕에 우연히 넘어간 버그였음
- 필요한 자료구조를 정확히 고르는 감각(카운팅이 필요 없으면 Map보다 Set)이 카카오 코테/면접에서 종종 물어보는 포인트라 앞으로 문제 풀 때 "이 값을 실제로 쓰는가"를 먼저 체크하고 자료구조를 고르기로 함
