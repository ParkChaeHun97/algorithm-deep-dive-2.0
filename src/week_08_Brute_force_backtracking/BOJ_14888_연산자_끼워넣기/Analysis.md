## 백준 14888 - 연산자 끼워넣기

### 문제
N개의 숫자와 N-1개의 연산자(+,-,×,÷ 각각 개수 주어짐)가 있을 때, 숫자 순서는 고정하고
연산자만 배치해서 만들 수 있는 식의 결과 중 최댓값과 최솟값을 구하는 문제.
연산자 우선순위 무시하고 앞에서부터 계산, 나눗셈은 음수를 양수로 나눌 때 C++14 기준
(양수로 바꿔 몫을 취한 뒤 음수로 되돌림) = 0을 향해 버림(truncate toward zero) 방식.

### 접근
- N-Queen보다 단순한 형태의 백트래킹: 가지치기 조건 없이, depth(연산자를 놓은 개수)가
  N-1이 되면 그때까지의 result를 max/min과 비교
- 연산자 종류별 개수를 배열(operators[4])로 관리하며, 사용 가능한(개수>0) 연산자만 시도
- 재귀 호출 전 해당 연산자 개수 하나 차감, 재귀에서 돌아오면 다시 복구(백트래킹)
- Java의 정수 나눗셈이 기본적으로 0을 향해 버리는 방식이라 문제가 요구하는 C++14 기준과
  동일하게 동작 → 별도의 음수 처리 코드 없이 result / numbers[...]로 충분함을 확인

### 실수
- 코드 자체는 실수 없이 정확하게 작성됨
- 실수는 오히려 검증 과정에서 발생함: 예제 입력(N=3, 1 2 3, 0 1 0 1)에 대한 예상 출력을
  "6, 1"로  AI가 문제를 잘못 제시함 → 실제로 이 입력에서 가능한 경로는 두 가지뿐이며
  (1-2)/3=0, (1/2)-3=-3 이 정답(최대 0, 최소 -3)이었음. 코드가 이미 정확했는데
  잘못된 예제 때문에 코드에 문제가 있다고 오해할 뻔함
- 실제 로그(depth별 result 출력)를 직접 찍어서 손으로 역추적한 뒤에야 예제 쪽이
  틀렸다는 것을 확인함

## 회고
- 이번 문제는 백트래킹 자체보다 "검증 기준(예제)이 틀렸을 가능성"을 의심하고 직접 로그를 찍어
  역추적하는 과정이 더 중요한 학습 포인트였음. 코드가 이상해 보일 때 무조건 코드부터 의심하지
  않고, 로그를 남겨 단계별로 직접 계산값을 대조하는 디버깅 방식이 유효했음
- 나눗셈 규칙(C++14 방식 = Java 기본 정수 나눗셈과 동일)을 문제 설명에서 정확히 확인하고
  넘어간 것도 다음에 비슷한 문제를 풀 때 재사용할 수 있는 지식으로 남음
