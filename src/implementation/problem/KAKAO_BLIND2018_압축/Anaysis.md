# [3차] 압축 (2018 KAKAO BLIND RECRUITMENT, 프로그래머스 Lv2)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/17684

## 문제

영문 대문자로 된 문자열 msg를 LZW 방식으로 압축해서 출력되는 사전 색인 번호를 배열로 반환하기. 사전은 A~Z(1~26)로 초기화하고, 현재 입력과 일치하는 가장 긴 문자열 w의 번호를 출력한 뒤 입력에서 w를 지우고, 다음 글자 c가 남아 있으면 w+c를 새 번호로 사전에 등록하는 과정을 반복함.

## 접근

- `HashMap<String, Integer>`로 사전을 만들고 `"A"`~`"Z"`에 1~26을 넣음. 새 단어 번호는 27부터
- 현재 위치 i에서 j를 한 칸씩 늘리면서 `msg.substring(i, j+1)`이 사전에 있는 동안 계속 늘려서 가장 긴 w를 찾음
- w의 번호를 리스트에 넣고, `j < msg.length()`면 다음 글자까지 붙인 `msg.substring(i, j+1)`(= w+c)을 사전에 등록
- `i += w.length()`로 처리한 만큼 이동. 길이 1인 단어가 전부 사전에 있어서 w는 최소 한 글자라 무한 루프가 생기지 않음
- 마지막에 `list.stream().mapToInt(Integer::intValue).toArray()`로 `int[]` 변환. 튜플에서 배운 List→배열 변환 패턴을 그대로 씀
- 문제에 적힌 5단계 과정을 코드로 그대로 옮긴 구조라 단계별로 대응이 명확함

## 회고

- 검증은 공식 예제(`KAKAO`, `TOBEORNOTTOBEORTOBEORNOT`, `ABABABABABABABAB`)와 한 글자 입력, 그리고 교과서식 LZW를 따로 짜서 랜덤 문자열 5만 개를 비교하는 방식으로 했고 전부 일치했음
- w+c를 따로 조립하지 않고, 가장 긴 w를 찾다가 멈춘 위치 j를 그대로 써서 `substring(i, j+1)`로 등록한 게 깔끔했음. 멈춘 그 지점이 곧 "w 다음 글자"라서 같은 값을 두 번 계산할 필요가 없음
- `substring`이 매번 새 문자열을 만들어서 최악의 경우 O(n²)이지만 입력 길이 제한이 작아서 문제없음
- 2020 블라인드의 "문자열 압축"과 이름은 비슷하지만 전혀 다른 문제임. 그쪽은 단위 길이별로 잘라서 반복을 세는 문제고, 이쪽은 사전을 키워가는 LZW 구현
