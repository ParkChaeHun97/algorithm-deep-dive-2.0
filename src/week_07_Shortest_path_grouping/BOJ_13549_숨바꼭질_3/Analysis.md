## 백준 13549 - 숨바꼭질 3

### 문제
점 N에서 점 K로 이동. X-1 또는 X+1 이동은 1초, X*2 순간이동은 0초.
동생을 찾는 가장 빠른 시간을 구하는 문제. 가중치가 0/1뿐이라 0-1 BFS(또는 다익스트라)로 풀어야 함.
+1/-1을 먼저 시도하는 순서에 따라 답이 달라지는 반례가 있어, 임의 순서 처리 대신
정확한 최단거리 알고리즘이 필요함.

### 접근
- 1261과 동일한 뼈대, 정점만 2차원 좌표 대신 1차원 위치(0~100,000)로 바뀜
- X+1, X-1은 가중치 1 / X*2는 가중치 0
- 이번엔 PQ(다익스트라) 방식으로 구현: `dist[]` 1차원 배열, PriorityQueue에 [위치, 누적거리] 저장
- 갱신 조건과 `d > dist[node]` 스킵 조건은 1261과 동일하게 적용

### 헷갈렸던 지점 / 실수
- **dist 배열 크기**: `new int[K+1]`로 잡았다가, 경로 중 K보다 큰 위치를 거쳐가는 경우가 있을 수 있어 전체 범위(0~100,000)인 `new int[100001]`로 수정
- **이동 조건을 K 기준으로 잘못 검사**: `node+1 < K` 등으로 조건을 걸어서 K 근처/이상으로 이동하는 경로 자체가 막혀버리는 버그. 이동 가능 여부는 K가 아니라 전체 좌표 범위(0~100,000) 기준으로 판단해야 함을 확인
- **PQ에 넣는 값이 상수였음**: `queue.offer(new int[]{node+1, 1})`처럼 실제 누적 거리(d+1)가 아니라 고정된 상수 1, 0을 넣던 실수 → 실제 갱신된 dist 값을 넣도록 수정
- **경계 조건 부등호 실수**: `node+1 < 100000`, `node-1 > 0`, `node*2 < 100000`처럼 부등호에 등호가 빠져서 정확히 0 또는 100000에 도달하는 이동이 막히는 문제 발생 → 전부 `<=`, `>=`로 수정 (좌표 범위가 0 이상 100000 이하이므로 경계값도 포함해야 함)

## 회고
- 1261에서 다진 0-1 BFS/다익스트라 뼈대(갱신조건, 스킵조건)를 다른 문제(1차원 좌표)에 그대로 적용하는 연습이 됨
- 오늘 실수는 대부분 "경계값 처리"에 몰려 있었음: 배열 크기, 이동 가능 조건, 부등호의 등호 포함 여부. 원리 이해보다는 문제의 정확한 범위 조건(0 ≤ X ≤ 100,000)을 코드에 정확히 반영하는 꼼꼼함이 부족했던 부분
- 이번엔 0-1 BFS(Deque) 대신 PQ(다익스트라) 버전으로 풀었는데, 가중치가 0/1뿐인 경우 다익스트라로 풀어도 정답이라는 것도 확인함. Deque 버전은 다음에 같은 문제로 다시 연습 예정
