## 카카오 2021 - 신규 아이디 추천

### 문제
신규 유저가 입력한 아이디를 7단계 규칙(소문자 변환 → 허용문자 외 제거 → 연속 마침표
합치기 → 앞뒤 마침표 제거 → 빈 문자열이면 "a" → 16자 이상이면 15자로 자르고 마지막
마침표 제거 → 2자 이하면 마지막 글자 반복해서 3자로)에 따라 순서대로 변환해 추천
아이디를 반환하는 문제. 알고리즘보다 문자열 처리 단계를 빠짐없이 정확히 구현하는
능력을 보는 9주차 첫 실전 문제.

### 접근
- 7단계를 각각 별도 메서드로 분리해 순서대로 적용 (가독성 + 디버깅 용이성)
- 초기에는 배열 순회 + replace + split 방식으로 구현했다가, 정규식(replaceAll)으로
  리팩토링하여 코드 간결화
    - 허용 문자 외 제거: `[^a-z0-9\\-_.]`
    - 연속 마침표 합치기: `\\.{2,}` → `.`
    - 앞뒤 마침표 제거: `^\\.|\\.$` → ""

### 헷갈렸던 지점 / 실수
- **허용 문자를 삭제 대상에 포함하는 실수**: 초기 구현에서 `-`(하이픈)와 `_`(밑줄)를
  삭제할 문자 리스트에 잘못 포함시켜, 원래 유지되어야 할 문자가 지워지는 반례 발생
  → 삭제 리스트에서 제외하거나 정규식의 허용 목록에 포함시켜 해결
- **substring 인덱스 off-by-one 실수**: "첫 15자만 남긴다"를 `substring(0, 15+1)`로
  구현해 실제로는 16자가 남는 오류 → `substring(0, n)`은 "0번부터 n-1번까지, 즉 길이
  n짜리 문자열"이라는 것을 다시 확인하고 `substring(0, 15)`로 수정
- **조건문 중첩 누락**: 15자로 자른 뒤 "마지막이 마침표면 제거"하는 로직을 별도의 if문으로
  분리해뒀는데, 이게 바깥의 "16자 이상일 때만" 조건 밖에 있어서 16자 미만인 경우에도
  항상 실행되는 문제 → 빈 문자열에 대해 charAt을 호출하면 예외가 날 수 있는 잠재적
  위험까지 있어, 두 조건문을 중첩 구조로 수정
- **정규식 리팩토링 중 대괄호 오타**: `[^a-z0-9]\\-_.]`처럼 대괄호가 중간에 잘못 닫혀
  의도한 문자 클래스가 아닌 엉뚱한 패턴이 되는 실수 → `[^a-z0-9\\-_.]`로 대괄호를
  하나로 묶어 수정

## 회고
- 이번 문제는 알고리즘적 판단보다 "문제에 명시된 단계를 하나도 빠짐없이, 정확한 경계값으로
  구현하는" 능력이 핵심이었음. 실제로 나온 버그들(허용문자 오삭제, off-by-one, 조건
  중첩 누락, 정규식 오타)이 전부 이런 유형의 실수였고, 이게 카카오가 강조하는
  "복잡한 알고리즘보다 구현력을 본다"는 평가와 정확히 맞아떨어지는 경험이었음
- 반복문+substring으로 처리하던 로직을 정규식(replaceAll)으로 리팩토링하는 과정을
  거치며, 정규식이 문자열 처리 코드를 간결하고 실수 여지가 적게 만들어준다는 것을
  체감함. 다만 정규식 자체도 문법 실수(대괄호 오타)가 날 수 있어 검증이 필요함을 확인
- 앞으로 문자열 구현 문제를 풀 때 (1) 각 단계를 함수로 분리해 검증하기 쉽게 만들고,
  (2) 정규식을 적극 활용하되 패턴 자체를 테스트로 확인하는 습관을 유지할 계획
