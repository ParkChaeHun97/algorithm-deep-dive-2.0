# 예상 대진표 풀이 분석

## 1. 문제 요약
- N명(N은 2의 거듭제곱)이 1~N번을 받고, 인접한 번호끼리(1↔2, 3↔4, ...) 토너먼트를 진행합니다.
- 이긴 사람은 다시 번호를 1부터 순서대로 새로 받습니다.
- A번과 B번이 항상 이긴다고 가정할 때, 몇 번째 라운드에서 만나는지 구하는 문제입니다.

## 2. 내 접근 방식
1. 전체 범위를 `[left, right] = [1, n]`으로 둡니다.
2. 절반(`mid`)으로 쪼갰을 때 A, B가 같은 쪽에 있으면 그쪽으로 범위를 좁힙니다.
3. 서로 다른 쪽에 있으면 그 범위가 "둘이 처음 만나는 대진표 범위"입니다.
4. 그 범위의 크기(`right - left + 1`)를 2로 몇 번 나눌 수 있는지가 곧 라운드 수입니다.

### 예시 (n=8, a=4, b=7)
| 단계 | left | right | mid | 판단 |
|---|---|---|---|---|
| 1 | 1 | 8 | 4 | a=4는 왼쪽, b=7은 오른쪽 → 분리, break |

범위 크기 8 → 8→4→2→1, 3번 나눔 → 정답 3

## 3. 풀이 코드 요약
```java
int left = 1, right = n, mid = n / 2;
while (true) {
    if (mid >= a && mid >= b) right = mid;          // 둘 다 왼쪽
    else if (mid < a && mid < b) left = mid + 1;    // 둘 다 오른쪽
    else break;                                     // 갈라짐
    mid = (left + right) / 2;
}
int power = right - left + 1;   // 포함 범위 크기
int result = 0;
while (power > 1) { result++; power /= 2; }
return result;
```

## 4. 50분이 걸린 이유 (회고)
- 빨리 찾은 것: 반으로 쪼개는 구조(이진 탐색 형태), 2의 지수로 나누는 횟수 = 라운드 수.
- 오래 걸린 것: 둘 다 **오른쪽 절반**에 있을 때 범위를 어떻게 줄이는지, 즉 `left = mid + 1` 로 해야 한다는 점.
- 범위 크기(`right - left + 1`)를 구하는 경계 처리는 빠르게 찾았습니다.

### 왜 오른쪽은 mid가 아니라 mid + 1인가
- `[1, 8]`을 반으로 나누면 `mid = 4`이고, 왼쪽 절반은 `[1, 4]`, 오른쪽 절반은 `[5, 8]`입니다.
- 왼쪽 절반의 **끝**은 `mid` 자체이므로 `right = mid` 입니다.
- 오른쪽 절반의 **시작**은 `mid` 다음 번호이므로 `left = mid + 1` 입니다. `left = mid`로 두면 4가 오른쪽 범위에 섞여 `[4, 8]`(5개)이 되어 절반이 아니게 됩니다.
- 즉 `mid`는 "왼쪽 절반에 속하는 마지막 원소"이며, 그래서 왼쪽은 `mid`까지, 오른쪽은 `mid + 1`부터입니다.
- 판별 조건도 같은 기준입니다. `mid >= a && mid >= b`이면 둘 다 왼쪽(`mid`가 왼쪽에 포함되므로 `>=`), `mid < a && mid < b`이면 둘 다 오른쪽입니다.

### 다음에 시간을 줄이는 방법
- 구현 전에 `[1, 8]`을 실제로 `[1, 4]`와 `[5, 8]`로 쪼개 적어 보고, 각 절반의 시작/끝이 `left`, `mid`, `mid + 1`, `right` 중 무엇인지 매핑해 둡니다.
- "mid는 왼쪽 절반의 마지막 원소"처럼 mid의 소속을 먼저 정해 두면 `mid` / `mid + 1` 선택에서 헤매지 않습니다.

## 5. 더 간단한 풀이 (비교용)
매 라운드마다 번호가 `(번호 + 1) / 2` 로 바뀐다는 점을 이용하면 범위 관리 없이 풀 수 있습니다.

```java
int round = 0;
while (a != b) {
    a = (a + 1) / 2;
    b = (b + 1) / 2;
    round++;
}
return round;
```

- 같은 번호가 되는 순간이 바로 만나는 라운드입니다.
- 이 문제의 본질은 이진 탐색이라기보다 **토너먼트 트리에서 두 노드의 최소 공통 조상(LCA)의 높이**를 구하는 것입니다.

## 6. 복잡도
| | 내 풀이 | 간단한 풀이 |
|---|---|---|
| 시간 | O(log N) | O(log N) |
| 공간 | O(1) | O(1) |

## 7. 배운 점 정리
1. 문제를 "범위를 반씩 줄이는 구조"로 본 것은 좋은 접근이었습니다.
2. `mid`는 왼쪽 절반의 마지막 원소이므로, 왼쪽으로 좁히면 `right = mid`, 오른쪽으로 좁히면 `left = mid + 1` 입니다. 쪼갠 뒤 각 절반의 경계를 먼저 적어 보는 습관이 필요합니다.
3. 구조를 찾은 뒤에는 "더 단순하게 표현되는 규칙(번호 갱신식)이 없는가?"를 한 번 더 생각해 봅니다.
4. 구현 전 작은 케이스(`[1, 8]` → `[1, 4]`, `[5, 8]`)를 손으로 쪼개 보면 경계 오류를 줄일 수 있습니다.
