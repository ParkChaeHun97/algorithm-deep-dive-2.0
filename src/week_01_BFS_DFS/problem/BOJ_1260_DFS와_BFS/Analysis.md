# 분석

## 1. 문제 요약
- 그래프를 DFS, BFS로 탐색한 결과를 각각 출력
- 입력으로 주어지는 정점 번호는 '양방향'
- 정점이 여러 개인 경우 정점 번호가 '작은 것' 부터 방문
- 방문이 끝나면 종료
- 정점 번호는 1번부터 N번까지

## 2. 입력
- 첫째 줄
  - 정점의 갯수 N, 간선의 개수 M, 탐색을 시작할 정점의 번호 V
  

## 3. 시간 복잡도
- 정점의 개수 N(1 <= N <= 1,000)
- 간선의 개수 M(1 <= M <= 10,000)
- 인접리스트를 사용한 BFS와 DFS는 O(V + E) = 11,000번의 최대 연산
- BFS와 DFS를 같이 출력하니 O(V + E) + O(V + E) = 22,000번의 최대 연산
- 정렬에서 사용되는 비용
  - Collections.sort() 는 TimSort 알고리즘을 사용하며 최악, 평균 모두 O(K log K), K는 리스트의 크기
  - 데이터 크기는 10,000이니 10,000 x 14 = 140,000 번
  - 양방향 그래프이니 140,000 x 2 = 280,000 번
  - 22,000 + 280,000 = 약 30만 번 연산의 시간 복잡도

    
## 4. 문제 해결
1. 자료구조는 List<Node>를 사용, Node 클래스는 정점 번호 id 와 간선을 이을 인접리스트 List<Node> adj를 사용
2. Node 클래스는 Comparable를 구현하여 id 기준으로 정렬을 할 수 있게 커스텀함
2. 핵심은 정점이 여러 개인경우 '작은 것'부터 방문
   - 방문 후 정점을 순회하기 전 Colletions.sort로 오름차순 정렬 후 방문

## 5. 디테일 채우기
- Collections.sort를 dfs, bfs 내부 함수에서 adj를 뽑아내서 정렬하는 방식을 사용 했었으나 main 함수 안에서 정렬을 수행하는 것으로 수정함
    - 내부에서 각각 뽑아내서 정렬을 수행하면 dfs와 bfs를 각각 한번씩 하기 때문에 정렬 비용이 두배로 듬
