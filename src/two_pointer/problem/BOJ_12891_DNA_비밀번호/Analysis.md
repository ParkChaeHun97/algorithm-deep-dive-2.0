## BOJ_12891 - DNA 비밀번호

### 문제
- 길이 S인 DNA 문자열(A,C,G,T로만 구성)에서 길이 P인 부분문자열(비밀번호 후보) 중
- 각 문자(A,C,G,T)가 지정된 최소 개수 이상 등장하는 것의 **개수**를 구하는 문제

### 접근
- 고정 크기 슬라이딩 윈도우
- 초기 윈도우(0~P-1)의 문자 카운트를 세팅한 뒤, 오른쪽으로 한 칸씩 밀면서
    - 나가는 문자(`left`) count--
    - 들어오는 문자(`right`) count++
- 매 윈도우마다 4개 문자 카운트가 조건을 모두 만족하는지 O(4)로 검사
- 전체 O(S)

### 헷갈렸던 지점
1. **check/count 배열 크기 오설정**: 문자 종류가 4개(A,C,G,T)로 고정인데, 배열 크기를 비밀번호 길이 `p`로 잡음. 문자 종류 개수와 윈도우 길이는 별개 개념인데 혼동한 것.
2. **초기화 루프 범위 실수**: 초기 카운트를 세우는 루프가 `p`가 아니라 `4`로 고정되어 있어서, 처음 윈도우 전체(`p`글자)가 아닌 앞 4글자만 세는 버그. 반대로 조건 비교 루프는 `4`여야 하는데 `p`로 되어 있는 등, `p`(윈도우 길이)와 `4`(문자 종류 수)의 역할을 여러 군데서 뒤바꿔 씀.
3. **문자→인덱스 매핑 불일치 (가장 반복된 실수)**: A/C/G/T를 배열 인덱스로 매핑하는 switch문이 초기화, left 처리, right 처리 세 군데에 중복 작성됨. 그 과정에서 G와 T의 인덱스가 서로 다르게 매핑되는 실수가 반복적으로 발생 — 한 군데를 고치면 다른 두 군데와 어긋나는 패턴이 여러 차례 반복됨. `check` 배열은 입력 순서(A,C,G,T)를 그대로 따르는데, `count` 배열 매핑이 이와 다르면 비교 자체가 무의미해짐.
4. **오른쪽 포인터 증가 순서 버그**: `right++`를 하기 전에 `dnaArr[right]`를 읽어서, 이미 카운트에 반영된 문자를 한 번 더 더하고 실제로 새로 들어와야 할 문자는 누락하는 버그. 포인터 증가와 배열 접근의 순서가 로직 정합성에 직결됨을 확인.
5. **while 종료 조건과 배열 범위**: `right < s`로 두면 루프 마지막 바퀴에서 `right++` 후 `dnaArr[right]`가 범위를 벗어남. `right + 1 < s`로 미리 여유를 둬야 함.

### 코드 작성 중 발생했던 실수들
1. 배열 크기: 문자 종류 수(4)와 윈도우 길이(p) 혼동
2. 루프 range: 초기화 루프와 비교 루프에서 `p`/`4`를 서로 반대로 사용
3. 문자-인덱스 매핑을 세 곳에 중복 작성하며 G/T 인덱스가 반복적으로 어긋남
4. 포인터 증가 순서와 배열 접근 순서 어긋남 (같은 문자 중복 반영)
5. while 조건 경계값으로 인한 배열 범위 초과 위험

### 회고
- 이번 문제의 핵심 실수는 대부분 "같은 정보(문자→인덱스 매핑)를 여러 곳에 중복 작성"한 데서 비롯됨. 초기화/제거/추가 세 지점에 각각 switch문을 손으로 다시 쓰다 보니, 한 곳을 수정해도 나머지가 안 맞는 상태가 여러 차례 반복됨.
- 다음부턴 `charToIdx(char c)` 같은 단일 함수로 매핑을 통합하면, 이런 종류의 불일치 버그를 원천 차단할 수 있음. "같은 로직을 두 번 이상 손으로 옮겨 적고 있다면 함수로 뽑아내라"는 원칙을 체감함.
- `p`(가변, 윈도우 길이)와 `4`(고정, 카테고리 수)처럼 의미가 다른 두 상수를 헷갈리지 않으려면, 매직 넘버 대신 `CHAR_KINDS = 4` 같은 이름 있는 상수로 명시하는 것도 방법.
