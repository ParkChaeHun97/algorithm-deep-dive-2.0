## 백준 2109 - 순회 강연

### 문제
N개의 강연이 주어지고, 각 강연은 (수익 p, 마감일 d)을 가짐. 각 날짜에는 강연을 하나만 배치할 수 있고, 강연은 마감일 이전(포함)에만 배치 가능. 총 수익을 최대화하는 문제. 대표적인 그리디 스케줄링(Job Sequencing) 유형.

### 접근
- 수익(p) 내림차순, 동일하면 마감일(d) 오름차순으로 정렬
- 수익이 큰 강연부터 순서대로 배치를 시도
- 배치할 때는 **마감일 d부터 거꾸로 내려가며 비어있는 날을 찾아 배치**
  → 가능한 한 늦은 날짜에 배치해야 앞쪽 날짜를 마감일이 더 급한 다른 강연에게 양보할 수 있음
- `used[]` 배열로 날짜별 사용 여부 체크
```java
for (int i = 0; i < n; i++) {
    int p = lectures[i][0];
    int d = lectures[i][1];
 
    // d일부터 거꾸로 내려가며 빈 날 찾기
    for (int day = d; day >= 1; day--) {
        if (!used[day]) {
            used[day] = true;
            result += p;
            break; // 배치 완료, 다음 강연으로
        }
    }
}
```

### 헷갈렸던 지점
- 처음엔 수익 기준 정렬만 하고, 배치 가능한 날짜를 앞에서부터(1일부터) 순서대로 채우려고 시도함 → 이 경우 뒤에 오는(수익은 낮지만 마감이 급한) 강연이 배치될 자리를 미리 뺏기는 문제가 생김
- 핵심은 "정렬 순서"가 아니라 "배치 방향"이었음: 마감일에서부터 거꾸로 내려가며 가장 늦은 빈 날에 꽂아야, 그 앞쪽 날짜들이 마감이 더 급한 다른 강연을 위해 남아있게 됨
- 즉 그리디의 핵심 트릭이 정렬 기준이 아니라 "각 강연을 최대한 늦게 배치한다"는 배치 전략에 있었다는 걸 못 짚고 있었음
## 회고
- 단순 정렬 + 순차 배치만으로는 안 되고, "마감일 역순 탐색"이라는 배치 전략이 그리디의 핵심이라는 걸 새로 이해함
- 이후 비슷한 스케줄링 유형(수익/마감일 조합) 문제를 보면, 정렬 기준뿐 아니라 배치 방향(앞에서부터 채울지 뒤에서부터 채울지)도 같이 고민해야 한다는 교훈을 얻음
