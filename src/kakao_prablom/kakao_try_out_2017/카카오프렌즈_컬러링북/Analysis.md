# 카카오프렌즈 컬러링북 (2017 카카오코드 예선, 프로그래머스 Lv2)

## 문제

m×n 크기의 그림에서 같은 숫자가 상하좌우로 이어진 칸들을 하나의 영역으로 볼 때, 영역의 개수와 가장 큰 영역의 크기를 구하기. 0은 색칠하지 않은 칸이라 영역으로 세지 않음.

## 접근

- 모든 칸을 순회하면서 `picture[i][j] != 0`이고 아직 방문하지 않은 칸을 만나면 새 영역의 시작점으로 보고 `numberOfArea++`, 거기서 BFS를 돌림
- BFS는 같은 번호인 이웃 칸만 큐에 넣고, 칸을 큐에 넣는 시점에 바로 `visited`를 찍음. 큐에서 꺼낸 개수가 아니라 넣을 때 센 개수가 곧 영역의 크기
- 각 BFS가 반환한 크기 중 최댓값이 `maxSizeOfOneArea`. 모든 칸을 한 번씩만 방문하니까 시간복잡도는 O(m·n)
- 전체가 0인 그림은 영역도 크기도 0이라 `[0, 0]`이 나옴

## 헷갈렸던 지점

- 처음에는 가장 큰 영역의 숫자와 그 영역 주변이 이어지는 영역이 가장 큰 숫자를 세는줄 알았으나 문제를 바로 읽고 0을 제외한 이어진 영역을 세는 형식으로 바로고침

## 실수

- 시행착오는 헷갈렸던 지점의 가장큰 영역을 세려고 HashMap에 저장하려고 `HashMap<Integer, Integer> map`을 선언 해놓았으나, 사용하지 않아서 죽은코드가 되었음
    - `visited`를 큐에서 꺼낼 때도 찍고 있었음. 이웃을 넣을 때 이미 찍으니까 필요한 건 시작 칸뿐이라, 시작 칸을 큐에 넣기 전에 한 번만 찍도록 정리함
    - `LinkedList` 대신 `ArrayDeque`로, `dx`/`dy`는 `final`로 바꿈

## 회고

- 이 문제는 전역에 값이 바뀌는 상태를 두면 테스트케이스 사이에 값이 남아서 틀릴 수 있다는 주의가 있음. 값이 바뀌는 건 전부 `solution`과 `bfs`의 지역 변수와 파라미터로 처리해서 피했음
- 방향 배열의 이름 `dx`/`dy`를 알고스팟 때와 반대로(행을 `dx`로) 쓰고 있음. 동작엔 문제없지만 문제마다 뒤집히면 헷갈리기 쉬워서, 행이면 `dr`/`dc`처럼 이름을 고정하는 습관이 필요함
- 검증은 공식 예제와, 유니온파인드로 따로 짠 정답을 기준으로 한 랜덤 3만 케이스 비교로 했고 전부 일치했음. 알고스팟 때 익힌 `visited`를 방문 시점에 찍는 BFS 패턴이 그대로 쓰였음
