## 백준 1764 - 듣보잡

### 문제
듣도 못한 사람 명단(N)과 보도 못한 사람 명단(M)의 교집합을 찾아
사전순으로 출력. 각 명단 내 중복 이름은 없음(문제에 명시).

### 접근
- HashSet에 듣도 못한 사람 명단을 저장 (add)
- 보도 못한 사람 명단을 순회하며 contains()로 교집합 판별 → O(1) 조회
- 교집합 결과를 List에 모아서 Collections.sort()로 사전순 정렬
- BufferedReader + StringBuilder로 I/O 최적화

### 헷갈렸던 지점
- HashSet.contains()가 왜 평균 O(1)인지: hashCode() → 나머지 연산으로
  배열 인덱스 산출 → 배열 직접 접근(O(1))이라는 3단계 과정을 정확히 몰랐음
    - 배열 인덱싱이 O(1)인 이유(주소 계산 한 번으로 접근)까지 연결해서 이해
    - 똑같은 해쉬 코드라면 배열 인덱스가 똑같아서 해쉬 충돌이 일어나는데, 그 인덱스(버킷) 안에 리스트 형태로 여러 개를 저장함, 그 형태는 LinkedList
    - 같은 버킷에 여러 개가 쌓이면 그안에서 순차 탐색을 해야해서 이론적으로 O(1)이 깨짐
    - Java 8부터는 같은 버킷에 8개 이상 쌓이면 리스트 대신 레드-블랙 트리로 바꿔서 O(log n)까지 완화

### 회고
- "HashMap은 hashCode를 배열 인덱스로 변환해 O(1) 접근을
  가능하게 하고, 충돌 시 버킷 내부를 리스트(→트리)로 관리해 성능을 완화한다"
- 이중 for문(O(N*M)) 대신 HashSet(O(N+M))을 쓰는 이유를 개념부터
  설명할 수 있게 됨 → 면접에서 "왜 HashMap/Set을 썼나" 질문 대비 확실히 됨
