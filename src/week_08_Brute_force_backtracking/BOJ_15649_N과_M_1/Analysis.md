## 백준 15649 - N과 M (1)

### 문제
1부터 N까지의 자연수 중에서 M개를 고른 수열(순서가 다르면 다른 경우로 침, 중복 없음)을
사전순으로 모두 출력하는 문제. 백트래킹 기반 순열의 기본형.

### 접근
- `used[]` 배열로 이미 쓴 숫자를 체크, `numbers[]`에 현재까지 고른 수열을 저장
- `depth`(0부터 시작, 지금까지 채운 개수)가 M이 되면 완성된 수열 하나를 출력
- 매 depth마다 1부터 N까지 전체를 다시 훑되(`used`가 아닌 것만), 하나 선택 후 재귀,
  재귀에서 돌아오면 `used[i]=false`로 되돌리는 것이 백트래킹의 핵심
- depth와 배열 인덱스는 문제의 번호 체계(1~N)와 무관하게 0부터 시작하는 내부 진행 카운터

### 헷갈렸던 지점 / 실수
- **종료 조건에서 return 누락**: `if(depth==m){ 출력 }` 다음에 `return`이 없어서, 출력 후에도
  코드가 계속 아래 for문으로 흘러가 depth==m인 상태에서 또 재귀를 시도하는 버그 발생
  → 이상한 출력(0이 섞여 나오는 등)으로 이어짐. `return` 추가로 해결
- **불필요한 배열 재생성**: `numbers = new int[m];`을 종료 블록 안에 넣어뒀는데, 이것도
  return 누락과 겹쳐서 상태를 더 꼬이게 만든 원인 중 하나였음. 불필요한 코드라 제거함
- depth를 0부터 시작하는 이유(내부 진행 카운터 vs 문제 도메인 번호 체계의 차이)를
  질문하고 스스로 정리함

## 회고
- 재귀 백트래킹에서 "종료 조건은 찾았는데 return을 안 해서 계속 진행되는" 실수는 처음 겪어봤는데,
  꽤 흔한 유형의 실수라는 걸 알게 됨. 앞으로 재귀 함수 짤 때 종료 조건마다 return 여부를
  바로 확인하는 습관이 필요함
- 백트래킹의 핵심 동작(선택 → 재귀 → 되돌리기)을 depth와 used 배열의 상태 변화를 손으로
  추적하며 확실히 이해함
