# 타겟 넘버 (프로그래머스 Lv2)

## 문제
음이 아닌 정수 배열 `numbers`의 각 숫자 앞에 `+` 또는 `-`를 붙여 합이 `target`이 되는 방법의 수를 구한다.
- numbers 길이 2~20, 각 숫자 1~50, target 1~1000
- 예: `[1,1,1,1,1]`, target 3 → 5

## 접근
- 제약: 길이 ≤ 20 → 경우의 수 2^20 ≈ 100만, 완전탐색(백트래킹) 가능
- 한 층의 결정: `depth`번째 숫자에 `+`를 붙일지 `-`를 붙일지
- 깊이: 지금 처리할 숫자의 인덱스 (`numbers[depth]`)
- 종료: `depth == numbers.length`일 때 `sum == target`이면 1, 아니면 0 반환
- 되돌림: 없음. `sum`을 인자로 새로 만들어 넘기므로 원복할 상태가 없다
- 개수 집계: static 변수 누적 대신 **반환값 합산** (`add + subtract`)

```java
private int dfs(int[] numbers, int target, int depth, int sum) {
    if (depth == numbers.length) return sum == target ? 1 : 0;
    int add = dfs(numbers, target, depth + 1, sum + numbers[depth]);
    int subtract = dfs(numbers, target, depth + 1, sum - numbers[depth]);
    return add + subtract;
}
```

## 헷갈렸던 지점
- 메모 4칸 중 depth 칸을 비워뒀다. 코드에서는 `numbers[depth]`로 쓰면서 메모에는 안 적음
- 되돌림 칸에 "더한 걸 되돌린다"고 적었는데, 실제 코드는 되돌릴 게 없는 구조였다. 메모와 코드가 불일치
- 선택 칸에 "다음 번호"라고 썼으나 정확히는 "현재(depth번째) 번호"

## 실수
- 풀이 자체는 실수 없이 통과 (손으로 `[1,1,1,1,1]`/3 → 5, `[1,1]`/0 → 2 확인)
- 메모 실수만 있었음: 되돌림 칸이 코드와 달랐고 depth 칸이 비어 있었음
- 부분수열의 합에서 났던 `sum += arr[depth]`(인자에서 지역변수 변경) 버그는 이번에 반복하지 않음

## 부분수열의 합과 비교
- 같은 점: 원소마다 두 갈래로 모두 탐색, 깊이 = 원소 인덱스
- 다른 점: 이번엔 **모든 숫자를 반드시 사용**(+/- 중 택일)이라 공집합 문제가 없다. 부분수열은 "안 넣는다"가 가능해서 공집합 처리가 필요했음
