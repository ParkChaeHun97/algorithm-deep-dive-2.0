## 백준 1261 - 알고스팟

### 문제
N*M 미로에서 빈 방(0)은 자유롭게 이동, 벽(1)은 부숴야 이동 가능(부수면 빈 방처럼 됨).
(1,1)에서 (N,M)까지 이동할 때 부숴야 하는 벽의 최소 개수를 구하는 문제.
단순 BFS(visited만 체크)로 풀면 안 되고, 빈 방 이동=가중치 0, 벽 이동=가중치 1로 보는
0-1 BFS(또는 다익스트라) 문제.

### 접근
- 0-1 BFS: 가중치 1인 이동은 덱의 뒤(`addLast`)에, 가중치 0인 이동은 덱의 앞(`addFirst`)에 삽입
  → 덱 안 원소들이 항상 거리 오름차순을 유지하게 되어, 힙 없이도 다익스트라와 같은 효과
- 그래프 표현은 다익스트라 때와 동일하게 인접 리스트 개념을 쓰되, 이 문제는 2차원 좌표 자체가 정점
  → `dist[][]`를 2차원 배열로, deque에는 `[row, col, 거리]`를 저장
- 가중치는 "칸"이 아니라 "이동(간선)"에 붙는 것: 다음 칸이 0이면 가중치 0, 다음 칸이 1(벽)이면 가중치 1
- 갱신 조건은 다익스트라와 완전히 동일: `dist[cur] + weight < dist[next]`
- `d > dist[cx][cy]`로 낡은 정보 스킵하는 것도 다익스트라의 `continue`와 동일한 원리
- 결론적으로 "모든 경로를 다 따라가며 최솟값 갱신"이 아니라, "매 순간 가장 적게 부순 경로부터 우선 처리하고, 더 나쁜 경로는 스킵 조건으로 자동 걸러짐"

### 헷갈렸던 지점

**1. 가중치가 칸의 값(0/1)이라고 착각함**
- "0을 계속 처리하다 보면 1이 나온다"는 식으로 순차적 흐름처럼 오해했으나, 실제로는 매 이동마다 "다음 칸이 0인지 1인지"를 독립적으로 판단해서 그때그때 가중치를 정하는 것
- 정점도 1차원 정수 번호가 아니라 (row, col) 좌표 자체라는 걸 짚고 넘어감

**2. 벽을 "딱 한 번만" 부순다고 오해**
- (N,M)까지 가는 여러 경로 중 벽을 부순 총 횟수가 가장 적은 경로를 찾는 문제라는 걸 뒤늦게 이해함
- dist[row][col]은 "그 칸까지 오는 데 필요한 최소 벽 개수"를 의미


### 실수 (구현 단계)
- `deque.getFirst()`를 써서 무한루프 발생 위험 → `pollFirst()`로 수정 (getFirst는 제거하지 않고 조회만 함)
- `if (d > dist[x][y])`에서 시작점 좌표(x,y)를 계속 참조하는 실수 → 현재 처리 중인 좌표(cx,cy)로 수정
- `dist[nx][nx] = ...` 오타 → `dist[nx][ny]`로 수정
- 덱 앞/뒤 삽입 분기 조건을 `dist[nx][ny] == 0`(갱신된 절대값)으로 잘못 판단 → `weight == 0`(이번 이동의 가중치)로 수정해야 함을 확인
- 입력 파싱에서 grid 값을 `dist` 배열에 저장하는 실수 → `matrix` 배열에 저장하도록 수정

## 회고
- 오늘은 코드 구현 단계에서 유독 실수가 많았음. 다만 실수들의 공통점을 보면 알고리즘 원리(가중치 분기, 갱신 조건, 스킵 조건) 자체는 다 맞게 이해하고 있었고, 변수명 혼동·배열 혼동·실행 순서 같은 "구현 디테일"에서 걸린 것들이었음
- 코드를 짜고 나서 `main()`부터 한 줄씩 순서대로 "이 시점에 이 변수가 어떤 값을 가지는가"를 손으로 짚어보는 검증 습관이 필요하다는 걸 느낌
- 0-1 BFS 자체는 다익스트라의 뼈대(갱신 조건, 스킵 조건)를 거의 그대로 재사용하는 구조라는 걸 다시 확인함 — 유일한 차이는 "다음 처리할 것을 어떤 자료구조로 어떻게 뽑아내느냐"(힙 vs 덱 앞/뒤 삽입)뿐이었음
