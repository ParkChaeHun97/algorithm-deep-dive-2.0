## 다트 게임 (2018 KAKAO BLIND RECRUITMENT)

### 문제
0~10 사이의 정수와 문자 S, D, T, *, #로 구성된 dartResult 문자열이 주어질 때, 다트 게임 점수 계산 규칙(S/D/T는 1/2/3제곱, *는 현재와 직전 점수 2배, #는 현재 점수 마이너스)에 따라 총점을 계산하는 문제.

### 접근
- 문자열을 한 번만 순회(O(n))하며 세 가지 경우로 분기: 숫자/영문자(S,D,T)/기타(보너스 기호 *,#)
- `isNumber` 플래그로 "직전 문자가 숫자였는지"를 추적해, 두 자리 숫자(예: "10")를 하나의 점수로 합치는 로직 처리
- `shootIdx`(1부터 시작)로 몇 번째 기회인지 추적, S/D/T를 만날 때마다 `scores[shootIdx]`에 점수를 기록하고 `shootIdx` 증가
- `*`, `#` 처리 시 `bonusIdx = shootIdx - 1`로 "방금 막 기록된 점수"를 가리키도록 계산 — `*`는 해당 점수와 그 직전 점수(`bonusIdx - 1`)를 모두 2배, `#`는 해당 점수만 마이너스
- 최종적으로 `scores[1..3]`을 합산해 반환

### 리뷰 — 가독성/효율성
**가독성**
- 변수명(isNumber, shootScore, shootIdx, scores)이 역할을 명확히 드러내고, 세 가지 분기(숫자/영문자/기타)로 구조가 깔끔하게 나뉨
- 개선 여지: `if(c=='S') ... if(c=='D') ... if(c=='T')`가 독립된 if문 세 개로 되어 있음 — 현재는 문제없지만 "셋 중 하나만 해당"이라는 의도를 명확히 하려면 `else if`로 묶는 것이 더 안전한 습관
- 개선 여지: 배열 크기 `3+1`의 `3`이 매직넘버 — 상수로 추출하면 의도가 더 분명해짐

**효율성**
- 전체 O(n)으로 이미 효율적 (문자열을 한 번만 순회)
- 두 자리 숫자를 합치는 부분(`Integer.parseInt(Integer.toString(shootScore)+c)`)이 매번 int→String→합치기→다시 int로 변환하는 비효율이 있음 — `shootScore = shootScore * 10 + (c - '0')`처럼 순수 정수 연산으로 자릿수를 밀어 넣는 방식이 더 효율적이고, 다른 문제에서도 자주 쓰이는 관용구라는 점을 확인

## 회고
- 반례를 의심하고 검증하는 습관이 이번엔 오히려 "실제로는 안전한 코드"를 확인하는 방향으로도 작동함 — 의심되는 지점(음수 인덱스 가능성)을 끝까지 따라가 "왜 실제로는 발생하지 않는지"까지 논리적으로 확인한 것이 의미 있었음
- 검증 과정에서 직접 잘못된 기댓값을 대입해 스스로도 혼란을 겪었던 해프닝 — 반례를 만들 때 기댓값 자체를 정확한 규칙에 따라 재계산해야 한다는 점을 상기함 (반례 검증 도구 자체도 틀릴 수 있다는 교훈)
- 가독성/효율성 리뷰에서 나온 두 가지(else if 사용, 문자열 대신 정수 연산으로 자릿수 처리)는 다음 문제부터 바로 적용해볼 수 있는 실용적인 개선점
