## 실패율 (2018 KAKAO BLIND RECRUITMENT)

### 문제
N개 스테이지가 있는 게임에서, 각 유저가 현재 멈춰있는 스테이지 번호가 담긴 배열(stages)이 주어질 때, 실패율(해당 스테이지에 도달한 유저 중 클리어하지 못한 비율)이 높은 스테이지 순으로 번호를 정렬해 반환하는 문제. 실패율이 같으면 스테이지 번호가 낮은 순.

### 접근
- `Stage`라는 별도 클래스를 만들어 스테이지 번호(id)와 실패율(failureRate)을 함께 관리, `Comparable`을 구현해 정렬 기준을 클래스 자체에 캡슐화
- `compareTo()`에서 실패율 내림차순, 같으면 id 오름차순으로 이중 정렬 기준을 명확히 분리
- `stageCounts[N+2]` 배열로 각 스테이지에 멈춰있는 인원 수를 먼저 집계 (N+1까지 포함해 배열 크기를 여유 있게 잡아 클리어한 유저도 안전하게 카운트)
- `totalPlayers`를 "그 스테이지에 도달한 인원 수"로 두고, 스테이지를 순회하며 실패율 계산 후 해당 스테이지에서 막힌 인원만큼 차감 — 다음 스테이지의 도달 인원이 자연스럽게 갱신되는 누적 구조
- 분모(totalPlayers)가 0인 경우(아무도 도달하지 않은 스테이지)는 실패율을 0으로 처리하는 예외 처리 포함
- `Collections.sort()`로 `Comparable` 기준 정렬 후, id만 추출해 결과 배열 구성

### 특이사항
- 별다른 시행착오나 반례 없이 한 번에 완성 — Comparable을 활용한 커스텀 정렬 객체 설계, 누적 인원 차감 방식의 실패율 계산 모두 처음부터 정확하게 구현됨
- `compareTo()`를 통해 "정렬 기준이 두 개 이상일 때 우선순위를 어떻게 표현하는지"를 깔끔하게 보여주는 구조 — 실패율 비교를 먼저 하고, 동률일 때만 id 비교로 넘어가는 분기가 명확함

## 회고
- 정렬 기준이 여러 개인 문제에서 Comparator를 람다로 즉석에서 짜는 대신, Comparable을 구현한 전용 클래스(Stage)로 분리한 것 — 이번 주 계속 다뤄온 "역할을 명확히 분리하는" 설계 감각이 자연스럽게 이어짐
- 별도의 반례나 디버깅 없이 한 번에 통과 — 실패율 계산처럼 "누적하며 차감해나가는" 패턴에 대한 감이 자리잡은 것으로 보임
