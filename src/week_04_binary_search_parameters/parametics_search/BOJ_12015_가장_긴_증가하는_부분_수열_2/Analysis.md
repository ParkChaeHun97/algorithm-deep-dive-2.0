# BOJ 12015 - 가장 긴 증가하는 부분 수열 2

## 문제
수열 A에서 가장 긴 증가하는 부분 수열(LIS)의 길이를 구한다.
N ≤ 1,000,000 → O(n²) DP 불가, O(n log n) 필요.

## 복귀 배경
3주간 알고리즘 학습 공백 후 감 테스트 목적으로 재도전.
이전에 BOJ 11053(O(n log n) LIS)을 풀었던 기록이 있었으나
tails 배열 갱신 로직을 거의 기억하지 못한 상태에서 시작.

## 접근 - O(n²) DP 복습
먼저 기본 점화식부터 복원:
dp[i] = max(dp[j] + 1) for all j < i where A[j] < A[i]

처음엔 "바로 이전 원소"와만 비교하는 실수를 했으나,
A = {10, 20, 10, 11, 12, 13} 반례로 검증하며
"i 이전의 모든 j"를 확인해야 함을 재확인함 (답은 4: 10,11,12,13).

## 접근 - O(n log n) tails 배열
핵심 개념: tails[k] = 길이 k+1인 증가 부분수열 중 마지막 원소의 최솟값

동작:
1. 새 원소 x에 대해 tails에서 "x 이상인 첫 위치"를 이분탐색(lower_bound)으로 탐색
2. 그 위치를 x로 교체 (없으면 맨 뒤에 추가, size++)
3. 최종 size가 LIS 길이

### 헷갈렸던 지점
tails 배열이 "실제 LIS 수열"이 아니라 "최적화를 위한 보조 배열"이라는 점.
A = {20, 10, ...} 순서에서 10이 20 자리를 교체하는 게
직관적으로 이상하게 느껴졌으나, tails[k]는 원본 순서를 보존하는 게 아니라
"미래에 가장 유리한 최솟값"을 유지하는 용도임을 이해.
→ 답(길이)만 정확하면 되고, tails 자체가 정답 수열일 필요는 없음.


## 회고
- 3주 공백 후에도 O(n²) DP 점화식과 이분탐색 템플릿(lowerBound)은
  틀 자체는 기억하고 있었음 → 완전히 감이 죽은 상태는 아니었음
- tails 배열의 "의미"를 개념적으로 이해하는 데 가장 시간이 걸림
