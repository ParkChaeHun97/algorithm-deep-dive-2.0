## 백준 11286 - 절댓값 힙

### 문제
절댓값이 가장 작은 값을 꺼내는 우선순위 큐 구현.
절댓값이 같으면 음수를 먼저 꺼냄.

### 접근
- PriorityQueue<Integer>에 Comparator를 커스텀해서 해결
- 비교 기준을 2단계로 설계:
    1. 절댓값 차이(Math.abs(a) - Math.abs(b))가 0이 아니면 그대로 리턴
    2. 절댓값이 같으면(0이면) a - b 리턴 → 음수가 자연히 앞으로 옴
     - 0, -1, 1, -3, 3, 4, -5, 7, -9, 10 이런식으로 정렬됨
- I/O는 BufferedReader + StringBuilder로 처리 (N ≤ 100,000이라 Scanner/println 남발 시 시간초과 우려)

### 헷갈렸던 지점
- Comparator.compare(a, b)의 리턴값이 a나 b 값 자체가 아니라
  "누가 앞에 와야 하는지"를 나타내는 정수라는 개념 자체가 처음엔 헷갈림
    - 음수 리턴 → a가 앞
    - 양수 리턴 → b가 앞
- 절댓값이 같을 때 왜 단순히 a - b만 리턴해도 음수가 먼저 오는지
  → 음수는 항상 양수보다 값 자체가 작다는 성질 이용


### 회고
- Comparator 두 단계 비교 로직(1차 기준 → 동률 시 2차 기준)은
  앞으로 정렬 기준이 여러 개인 문제에서 계속 쓸 패턴이라 확실히 익힘
