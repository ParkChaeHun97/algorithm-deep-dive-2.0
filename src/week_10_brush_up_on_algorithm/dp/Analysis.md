### 1. BOJ 2579 - 계단 오르기

**문제**
계단을 한 칸 또는 두 칸씩 오르되, 연속된 세 계단을 모두 밟을 수 없고 마지막 계단은 반드시 밟아야 할 때, 얻을 수 있는 최대 점수를 구하는 문제.

**접근**
- 상태를 두 개로 나눠서 관리: `dp_one[i]`(i를 한 칸으로 도착), `dp_two[i]`(i를 두 칸으로 도착)
- `dp_one[i] = dp_two[i-1] + arr[i]` — i-1을 반드시 "두 칸으로" 왔어야 i-2를 안 밟은 상태가 보장되어 연속 3칸을 피할 수 있음
- `dp_two[i] = max(dp_one[i-2], dp_two[i-2]) + arr[i]` — i-2까지는 어떻게 왔든 상관없음 (i-1을 안 밟으니 연속 3칸 문제 자체가 안 생김)
- N==1인 경우는 입력 줄 수 자체가 다르므로 별도 분기 처리 필요

**실수**
- `dp_two[2]` 초기값을 `dp_one[0]`처럼 존재하지 않는 0번째 계단을 참조해서 계산하려 함 — 시작점에서 바로 2칸 뛰는 경우이므로 그냥 `arr[2]`가 답
- `dp_two[i]` 점화식에서 `dp_two[i-2]`를 써야 하는데 `dp_two[i-1]`로 인덱스를 잘못 적음
- N==1 예외 처리를 `input()` 함수 안에서 출력 후 `return`했는데, `main`에서 그 뒤 무조건 `dp()`를 또 호출해 중복 출력/NPE 위험 발생 → `input()`이 N==1 여부를 리턴하도록 구조를 바꿔 `main`에서 분기하도록 수정

**토론한 내용**
- 왜 `dp_one[i]`는 i-1의 `dp_two`만 보고, `dp_two[i]`는 i-2의 `dp_one`/`dp_two` 둘 다 봐야 하는지 — "i-2를 밟았는지 여부"가 연속 3칸 규칙과 직결된다는 점을 반례 경로("2,3,4번 연속 밟기")로 직접 확인하며 이해함

### 2. BOJ 11053 - 가장 긴 증가하는 부분 수열 (LIS)

**문제**
수열에서 가장 긴 증가하는 부분수열의 길이를 구하는 문제 (순서 유지, 연속일 필요는 없음).

**접근**
- `dp[i]` = "i번째 원소를 마지막으로 사용하는" 가장 긴 증가 부분수열의 길이로 정의
- `dp[i] = 1`로 초기화 (최소한 자기 혼자는 길이 1)
- i보다 앞선 모든 j(1~i-1)를 순회하며 `arr[j] < arr[i]`이고 `dp[j]+1 > dp[i]`이면 갱신
- 최종 답은 `dp[n]`이 아니라 **dp 배열 전체의 최댓값**

**실수**
- 처음에 "직전 원소와만 비교"하는 방식(`dp[i] = dp[i-1]+1` or `dp[i-1]`)으로 접근함 — 이는 연속 증가 구간의 길이를 세는 것이지 LIS가 아님. 반례 `[7,4,2,8,1,7,7,10]`로 오답(4) 확인, 정답은 3
- 이중 for문으로 고친 뒤에도 `else dp[i] = dp[i-1]`을 추가로 넣는 실수 — 안쪽 루프가 돌 때마다 조건 불만족 시 애써 갱신한 dp[i] 값이 `dp[i-1]`로 덮어써짐. else를 아예 없애고 조건 불만족 시 아무것도 안 하도록 수정
- `System.out.println(dp[n])`으로 마지막 원소 기준 값만 출력 — 반례 `[1,2,3,4,1]`(정답 4)에서 `dp[5]=1`이 나와 오답. `dp[i]`의 정의(“i를 반드시 마지막으로 쓰는”)와 “전체 배열의 정답”이 다르다는 걸 반례로 확인 후, 매 i마다 `maxValue`를 갱신하는 방식으로 수정

**토론한 내용**
- "브루트포스면 2^N, DP는 O(N²)"라는 차이가 왜 생기는지 — 부분 문제의 답(dp[j])을 저장해두고 재사용하기 때문이라는 점을 짚음
- i=6, i=8(값 10) 케이스를 직접 손으로 후보를 다 나열해보며, "일부만 골라서 맞히는" 방식이 아니라 매번 모든 j를 다 확인해야 한다는 걸 확인

### 3. BOJ 1912 - 연속합

**문제**
수열에서 연속된 부분수열 중 최대 합을 구하는 문제 (하나 이상 선택 필수).

**접근**
- `dp[i]` = "i번째 원소를 반드시 포함하고 i에서 끝나는" 연속 부분합의 최댓값
- 선택지 두 가지: `dp[i-1] + arr[i]`(이어붙이기) vs `arr[i]`(새로 시작하기), 둘 중 큰 값
- 매 i마다 `maxValue`를 갱신해 전체 최댓값을 추적

**실수**
- 없음 — 이전 두 문제에서 겪은 시행착오(브루트포스 나열 → 압축 지점 발견)를 거친 뒤라 첫 시도에 점화식, 초기값, 최댓값 추적까지 모두 정확하게 구현함

**토론한 내용**
- N=4까지 모든 경우의 수를 직접 손으로 나열(`10+(-4)+3+1`, `(-4)+3+1`, `3+1`, `1` 등)하다가, 앞의 세 후보가 사실 "dp[3]+1" 하나로 압축된다는 걸 스스로 발견함 — 이 나열 과정이 점화식을 찾는 데 가장 효과적이었다고 밝힘

## 회고
- DP 코드를 실제로 구현하는 능력(배열 채우기, 인덱스 관리, 엣지케이스 처리)은 세 문제를 거치며 눈에 띄게 늘었음 — 반례를 보고 스스로 버그를 찾아내는 수준까지 도달
- 반면 점화식을 처음 세우는 단계는 세 문제 모두 힌트가 필요했음 — "코드 짜기(번역)"와 "부분 문제로 쪼개기(설계)"가 서로 다른 역량이라는 걸 체감함
- 연속합 문제에서 작은 사이즈(N=3~4)의 경우의 수를 직접 브루트포스로 나열해본 것이 점화식의 압축 구조를 스스로 발견하는 데 가장 효과적이었음 — 앞으로 새로운 DP 문제를 만나면 코드부터 짜지 않고 작은 예제를 손으로 나열해보는 걸 우선 시도해보기로 함
- 오늘의 사고 과정 패턴 정리: (1) "i번째를 어떻게 정의할지" 먼저 정하기 → (2) "i에 도달하는/포함하는 경우의 수" 나누기 → (3) 각 경우가 참조해야 할 이전 상태(dp[i-1], dp[i-2], dp[j]) 파악하기
