## 크레인 인형뽑기 게임

### 문제
board(격자판, 인형 배치)와 moves(크레인이 선택하는 열 번호 순서)가 주어질 때, 각 열에서 맨 위 인형을 뽑아 바구니에 쌓다가 연속으로 같은 인형이 오면 터뜨리는 규칙으로, 총 터진 인형의 개수를 구하는 문제.

### 접근
- `List<Deque<Integer>>`로 각 열(column)을 하나의 덱으로 관리 — board를 행 우선으로 순회하되, 각 열에 대해 `offerFirst()`로 넣어 **위에서부터 쌓이는 순서를 자연스럽게 표현**
- moves를 순회하며 해당 열에서 `pollLast()`로 맨 아래(=board 상에서는 맨 위) 인형을 뽑음
- 뽑은 인형을 비교용 `Stack<Integer>`(getDolls)에 쌓되, 스택 맨 위와 같으면 `pop()` 후 `boomDolls += 2`로 터진 개수 누적, 다르면 그대로 `push()`
- 열이 비어있는 경우(인형이 이미 다 뽑힌 상태에서 moves가 다시 그 열을 가리키는 경우)와 비교 스택이 비어있는 경우 각각 조건 분기로 예외 처리

### 특이사항
- 별다른 시행착오 없이 한 번에 완성
- `offerFirst()`로 2차원 배열을 열 단위 덱으로 변환하는 아이디어가 핵심 — board를 행 우선으로 순회하면서도 각 열의 "위에서부터 쌓인 순서"를 자연스럽게 재현한 부분이 깔끔함
- 인형 비교에 `int`(pickDoll, 자동 언박싱된 값)와 `Integer`(getDolls.peek())를 `==`로 비교했는데, 한쪽이 primitive int라 자동 언박싱되어 값 비교로 정상 동작함 — Integer 캐싱 범위(-128~127) 문제와 무관하게 안전한 코드

## 회고
- 2차원 배열 문제를 "각 열을 독립된 자료구조(Deque)로 분리해서 관리"하는 방식으로 접근한 것이 핵심적인 설계 포인트였음 — 격자를 그대로 인덱스로 다루기보다, 문제의 본질(열 단위로 쌓이고 뽑힌다)에 맞는 자료구조로 변환해서 접근한 점이 좋았음
- 최근 몇 문제(비밀지도, 실패율, 숫자 문자열과 영단어, 크레인 인형뽑기)가 연속으로 큰 시행착오 없이 한 번에 통과되고 있음 — 지난 2주간 반례 찾기, 구조 설계, 자료구조 선택 등에서 쌓인 감각이 실제로 안정화되고 있다는 신호로 보임
