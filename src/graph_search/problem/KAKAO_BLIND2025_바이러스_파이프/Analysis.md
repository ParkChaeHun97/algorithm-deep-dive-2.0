# 바이러스 파이프 (2025 카카오 하반기 1차, 프로그래머스)

## 문제

n개의 배양체가 n-1개의 파이프로 이어진 트리가 있고, 파이프는 A, B, C(1~3) 세 종류 중 하나이며 처음엔 전부 닫혀 있음. 배양체 하나가 감염된 상태에서, 같은 종류의 파이프를 한꺼번에 열었다가 닫는 행동을 최대 k번 반복해서 감염되는 배양체 수를 최대로 만들기. 열린 파이프로 연결된 이웃은 감염되고, 한 종류를 열었으면 닫기 전에 다른 종류를 열 수 없음. n은 100 이하, k는 10 이하.

## 접근

- 행동마다 파이프 종류를 1~3 중에서 하나 고르는 모든 순서를 재귀로 만듦. 같은 종류를 여러 번 열 수 있어서 중복을 허용하는 순열이고, 경우의 수는 3^k라 k=10이면 59,049개
- 순서 하나마다 시뮬레이션: `visited`를 새로 만들고 시작 노드를 감염시킨 뒤, 행동마다 이미 감염된 모든 노드에서 열린 종류의 파이프로만 BFS로 퍼뜨림
- 감염은 늘기만 하고 줄지 않아서 정확히 k번으로 고정해서 열거해도 최대 k번과 같은 답이 나옴
- 순서마다 감염된 개수를 세서 최댓값을 갱신

## 헷갈렸던 지점

- 문제를 처음 보고 `k`를 "파이프 종류의 수"로 받아들였음. 실제로는 종류가 1~3뿐이고 `k`는 열었다 닫는 횟수였음
- 파이프를 열었다 닫는 순서를 "각 종류를 한 번씩 쓰는 순열"로 생각했고, 같은 종류를 여러 번 열 수 있다는 걸 놓쳤음

## 실수

1. 경우의 수를 `1..k`의 순열(`used` 배열 사용)로 만든 것. 종류는 1~3뿐이고 반복이 가능해서 틀린 모델이었음
    - `k=1`이면 순열이 `[1]`뿐이라 A 파이프만 열어보고 B, C는 시도도 안 함
    - `k`가 3보다 크면 존재하지 않는 종류(4, 5, ...)를 여는 순서까지 만들면서 정작 같은 종류를 두 번 여는 순서는 못 만듦
    - 공식 예제 두 개는 우연히 순열과 맞아떨어져서(예제1은 B→A, 예제2는 A, B, C) 통과했고, 채점에서는 40개 중 5개만 통과해서 정확성 0점이었음
    2. `maxCount`와 `graph`를 `static`으로 둔 것. 테스트케이스 사이에 값이 남을 위험이 있어서 `solution` 안의 지역 변수로 옮겼음
3. `maxCount`를 `int`로 만들어 파라미터로 넘긴 것. 자바는 기본형을 값으로 복사해서 넘기기 때문에 안쪽에서 갱신해도 밖의 값이 안 바뀌어서 계속 -1이 반환됐음. 길이 1짜리 배열 `int[] maxCount = {-1}`로 감싸서 해결
4. 순열에서 `used`를 없앴을 때의 함정이 있었음. `depth == k`에서 `return`이 없으면 아래 `for`문으로 내려가 `numbers[k]`에 값을 쓰려고 해서 `ArrayIndexOutOfBoundsException`이 남. 이전엔 `used`가 전부 true라서 우연히 아무 일도 안 일어났던 것

## 회고

- 구현이 아니라 해석이 틀린 케이스였음. 코드는 처음부터 깔끔하게 돌아갔는데 "무엇을 어떻게 열거하는가"가 문제와 달랐음. 완전탐색을 짜기 전에 각 선택지가 무엇이고 같은 선택을 반복해도 되는지를 문제 설명에서 먼저 확인해야 함
- 예제가 통과한다고 맞는 게 아님. 폰켓몬 때처럼 예제가 우연히 버그를 가려준 케이스였고, 이번에는 예제 두 개가 모두 순열과 일치했음
- 채점이 40개 중 5개만 통과하는 패턴은 "구현 실수"가 아니라 "모델이 틀렸다"는 신호였음. 대부분 실패하는데 몇 개만 통과하면 입력의 일부(예: 종류가 우연히 순열과 맞는 경우)만 맞고 있다는 뜻이라 열거 방식을 의심해볼 만함)
- 값 전달 문제는 컬러링북에서 전역 상태를 조심한 것과 같은 계열의 주의사항임. 재귀에서 결과를 위로 올릴 때는 배열이나 반환값을 쓴다는 것을 기억해둠
- 시간초과 대비로 행동마다 감염된 노드를 전부 큐에 넣고 BFS를 한 번만 돌리는 방법이 있는데, 이번에는 필요 없어서 적용하지 않았음
