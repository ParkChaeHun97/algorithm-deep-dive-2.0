# K번째 수

## 백준 1300 (K번째 수)

### 문제
- N×N 배열 A[i][j] = i×j에서 모든 원소를 정렬했을 때 K번째 수 구하기
- N=100,000이면 N²=10^10 → 배열을 직접 만들 수 없음

### 해결
- Parametric Search: "mid 이하인 원소가 몇 개인가"를 세는 방식
- 각 행 i에서 i×j ≤ mid를 만족하는 j의 개수: min(mid/i, N)
- 모든 행의 개수를 합산 → count를 K와 비교
- count >= K를 만족하는 가장 작은 mid = K번째 수
- O(N log(N²)) = O(N log N)으로 해결

### 예시
```java
N=3, K=7
배열:
1  2  3
2  4  6
3  6  9
정렬: [1, 2, 2, 3, 3, 4, 6, 6, 9]
↑ 1  ↑ 2  ↑ 3  ↑ 4  ↑ 5  ↑ 6  ↑ 7 = 6
mid=6일 때 count:

행 1: 1×j ≤ 6 → j ≤ 6 → min(6/1, 3) = 3개
행 2: 2×j ≤ 6 → j ≤ 3 → min(6/2, 3) = 3개
행 3: 3×j ≤ 6 → j ≤ 2 → min(6/3, 3) = 2개
총 8개 >= K(7) → 조건 만족

```

### 핵심 포인트
- N²이 최대 10^10 → right는 반드시 long (int 범위 초과)
- count도 long (누적 과정에서 오버플로우 가능)
- count >= K를 만족하는 **가장 작은 mid** = K번째 수 (이분탐색으로 우측 탐색)
- 각 행에서 min(mid/i, N)으로 N을 초과하지 않도록 처리
    - 예: mid=1000, i=1이면 mid/i=1000인데, N=100이면 실제로는 100개까지만 존재

### 이분탐색 구조
 - count >= K:     answer = mid, right = mid - 1  (더 작은 값 탐색)
 - count < K:      left = mid + 1  (더 큰 값 필요)

### 배웠던 Parametric Search 패턴
- 2805 (나무 자르기): 조건 만족하는 최댓값 찾기 → left = mid + 1
- 1300 (K번째 수): 조건 만족하는 최솟값 찾기 → right = mid - 1
- 두 경우 모두 "조건 만족 시 answer 저장"이 핵심
