## 백준 1197 - 최소 스패닝 트리

### 문제
정점 V개, 간선 E개(양 끝 정점 A,B와 가중치 C)가 주어질 때, 모든 정점을 사이클 없이
연결하면서 가중치 합이 최소가 되는 트리(MST)의 가중치 합을 구하는 문제. 크루스칼 알고리즘의
전형적인 적용 문제.

### 접근
- 크루스칼의 목적: 다익스트라(특정 시작점에서 각 정점까지의 최단거리)와 달리, 그래프 전체를
  사이클 없이 최소 비용으로 연결하는 것. 시작점 개념 자체가 없음
- 간선을 [a, b, weight] 형태로 저장 후 가중치 기준 오름차순 정렬
- 정렬된 순서대로 순회하며 find(a) != find(b)(=사이클 안 생김)면 union 후 가중치 누적,
  같으면(=이미 연결됨) 스킵
- find/union은 1717, 1976에서 쓴 것과 동일한 구조 그대로 재사용

### 정리한 개념
- 동일/중복 간선 처리: 크루스칼은 별도의 중복 제거 로직 없이도, 사이클 체크(find(a)!=find(b))가
  자동으로 중복이나 비효율적인 간선을 걸러줌. 같은 정점 쌍이 여러 번 주어지거나 가중치가 다르게
  중복되어도, 정렬 순서상 가장 싼 것만 채택되고 나머지는 이미 union된 상태라 자동 스킵됨
- 결국 모든 정점이 같은 부모로 수렴하는 것 아닌가?: 이는 오류가 아니라
  MST의 정상적인 최종 상태. V개 정점을 모두 연결하려면 정확히 V-1개의 간선이 필요하고, 그 개수만큼
  채택되고 나면 모든 정점이 하나의 그룹(같은 대표)으로 합쳐짐. 크루스칼은 그 과정에서 "아직 다른
  그룹인 두 정점을 잇는" 간선만 하나씩 채택해나가는 방식

### 실수
- 없음 - 코드가 처음부터 정확하게 작성됨 (parent 초기화, N/E 구분, find/union 재사용, 경로 압축)

## 회고
- 지난 며칠간 반복됐던 실수 패턴(parent 배열 초기화 누락, 변수 범위등)이 이번엔 전혀 나타나지
  않음. 반복 연습을 통해 유니온 파인드 관련 기본기가 확실히 손에 붙었다는 걸 확인함
- 다익스트라와 크루스칼의 목적 차이(특정 시작점의 최단거리 vs 그래프 전체의 최소 연결 비용)를
  명확히 구분해서 이해했고, "왜 그리디로 간선을 골라도 항상 최적이 되는가"에 대해 사이클 체크와
  그룹 수렴 과정을 스스로 질문하며 정리함
- 7주차 전체 계획(BFS/DFS 복구 → 다익스트라 → 0-1 BFS → 유니온파인드 → 크루스칼)을 완주함
